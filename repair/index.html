Fit boundaries

A good match is narrow enough to verify

Good fit

  • A reproducible bug or broken user flow
  • A mobile or accessibility issue with clear impact
  • Regression tests around risky existing behavior
  • A contained React, TypeScript, or .NET modernization step

Usually not a fit

  • An undefined “build the whole startup” request
  • Work that requires unsupported access or unsafe handling of production secrets
  • Guaranteed business, security, medical, or legal outcomes
  • Open-ended support without a written scope

Common questions

What happens before any repair starts?

Do I need to share production credentials?

No. Start with the least access needed to reproduce the issue. Secrets should stay in your own approved secret-management system and can be added by you when necessary.

What if the diagnostic shows the repair is larger?

You receive the findings and a prioritized path. No repair begins until the scope, price, risks, and acceptance criteria are agreed in writing.

Can you work remotely?

Yes. The default workflow is remote and asynchronous, using written reproduction steps, repository access, and short review loops.

Are further adjustments included?

Quick iterations are welcome for adjustments inside the agreed acceptance criteria. A materially different request is scoped separately before work continues.
